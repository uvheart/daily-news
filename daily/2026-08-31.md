### 5. Agentic RL / RL Infra

#### 5.1 稳定 RNG 与 rollout 可复现性

- **事件日期：** 2026-08-29 左右。
- **摘要：** vLLM 社区提出 backend-stable stateless RNG RFC，动机是当前不同后端对随机数生成的依赖不完全一致，可能影响采样结果复现。对于 RL rollout，这会放大为跨节点、跨硬件、跨版本的 trajectory 差异。
- **核心技术点：** stateless RNG、cross-backend determinism、sampling reproducibility、seed semantics。
- **为什么重要：** 当训练和 rollout 解耦时，随机性不再只是模型参数之外的噪声，而是实验可重复性与评测一致性的基础。
- **来源链接：** [vLLM RFC #54143](https://github.com/vllm-project/vllm/issues/54143)

#### 5.2 新模型和新硬件让 rollout 验证矩阵变复杂

- **事件日期：** 2026-08-29 至 2026-08-31。
- **摘要：** vLLM 近期 issue 涵盖 GB10 上 Qwen3.8-Flash-Next 的非法内存访问、GLM-5.3-Flash 在 Ada 架构上的路径支持问题，以及量化与 fused shard 兼容性问题。对 Agentic RL 集群而言，这意味着“同一模型在不同 GPU 上跑通”不再是简单的部署动作。
- **核心技术点：** model architecture plugins、quantization kernels、GPU capability matrix、prefix caching、sparse/linear attention paths。
- **行业影响：** 训练/采样平台需要把硬件能力探测、模型能力注册、自动回归和降级策略做成平台能力。
- **来源链接：** [Qwen3.8-Flash-Next issue](https://github.com/vllm-project/vllm/issues/54173) · [GLM issue](https://github.com/vllm-project/vllm/issues/54059)

### 9. 对用户职业与技术路线的影响

#### 今天最值得深入学习的 3 个技术点

1. **长生命周期 Agent Session 的状态机设计：** 研究任务租约、checkpoint、resume、幂等执行、人工接管和资源 GC，最好用 Kubernetes + durable workflow 做一个最小可运行版本。
2. **RL rollout 的确定性与采样一致性：** 重点理解 stateless RNG、seed 传播、跨后端/跨 GPU 差异、trajectory schema 和 replay 可复现。
3. **Agent Sandbox 的系统级安全：** 把网络出口、凭证代理、文件系统、审计、资源回收和 kill switch 设计成统一 control plane，而不是把安全问题分散在容器参数里。

#### 可能形成岗位机会的趋势

- Agent Runtime / Environment Platform Engineer
- Agentic RL Infrastructure / Rollout Platform Engineer
- AI Inference Reliability / GPU Scheduling Engineer
- Sandbox Security / Control Plane Engineer

#### 更可能只是短期热点的内容

- 没有一手技术细节支撑的“AGI 已到来”叙事。
- 只展示 benchmark 峰值、没有成本、稳定性和恢复能力数据的推理宣传。
- 只把“支持某模型”作为卖点，但没有给出跨硬件和长上下文验证结果的框架更新。

#### 一个可执行的学习/实践建议

本周可以做一个最小实验：实现一个“持久化 Agent Sandbox Session”原型，包含以下链路：`create session → allocate workspace → issue lease → execute tool → checkpoint → resume → timeout GC`。同时给 rollout 增加统一 seed、trajectory ID、运行时配置指纹和失败快照。这个项目能把 Kubernetes、Sandbox、Agent Runtime 和 RL Infra 连接起来，比单独再做一个普通 CRUD 云平台项目更贴近下一阶段岗位。
