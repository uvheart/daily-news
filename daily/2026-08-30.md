## 5. Agentic RL / RL Infra

### verl：reward grader 出现模型输出可触发 RCE / reward forgery 的安全问题（Open PR，未合并）

- **日期：** 2026-08-29
- **状态：** **Open / 未合并**
- **PR：** `#7607 [reward] fix: remove eval() RCE in prime_math grader (CVE-2026-6878)`
- **摘要：** PR 描述指出 `prime_math` reward grader 的两个路径会把 model-authored answer 送入 Python `eval()`；攻击样本不只可执行任意代码，还可修改 worker 进程状态，让后续错误答案获得高 reward，从而污染 training curve、checkpoint selection 与 eval。
- **核心技术点：** reward function 不能默认可信；rule-based grader 也应放入隔离进程/沙箱并采用 fail-closed parser。
- **为什么重要：** Agentic RL 中 policy 本身就是“对 reward 系统的 adversarial input generator”。Reward worker 的权限边界应接近在线 judge/sandbox，而不是普通 Python util。
- **来源：** [verl PR #7607](https://github.com/verl-project/verl/pull/7607)

### verl：异步 AgentLoop 的 reward contract 不一致（Open PR，未合并）

- **日期：** 2026-08-29
- **状态：** **Open / 未合并**
- **PR：** `#7608 [reward] fix: DisRM returns reward_extra_info so async scoring does not KeyError`
- **摘要：** standalone DisRM path 只返回 `reward_score`，但 async AgentLoop consumer 无条件读取 `reward_extra_info`，导致 trajectory scoring 直接 KeyError。PR 通过统一 producer contract 并补 CPU/e2e regression test 修复。
- **判断：** 这类问题说明异步 RL pipeline 的难点越来越像 event-driven distributed system：每个 producer/consumer 的 schema、idempotency 和 failure semantics 必须明确。
- **来源：** [verl PR #7608](https://github.com/verl-project/verl/pull/7608)

## 6. Agent Sandbox / Runtime / Infra

### 从最近事件看，Sandbox 的“正确抽象”正在变化

Anthropic AAR 与 DeepMind 双盲 eval 共同指向一种更完整的 runtime：不仅要创建容器/VM，还要提供 **secret/benchmark 隔离、网络策略、artifact lineage、trajectory audit、hidden evaluator、资源 TTL、异常终止和可重放**。  
来源：[Anthropic AAR](https://alignment.anthropic.com/2026/automated-alignment-researchers/) / [DeepMind 双盲评测](https://deepmind.google/blog/piloting-the-worlds-first-double-blind-ai-evaluations/)

这意味着 Env-as-a-Service 如果只做 `create / exec / delete` 很容易沦为薄封装；更有价值的是做成 **Experiment / Agent Runtime Control Plane**，将 environment lifecycle 与 evaluation/security policy 一起抽象。

## 7. 训练 / RL / 推理框架与基础设施更新

### AReaL：修复 RTensor 删除失败后的资源泄漏（Merged）

- **日期：** 2026-08-28
- **状态：** **Merged**
- **PR：** `#1647 fix(infra): prevent leaks after RTensor delete failures`
- **摘要：** 删除远端 RTensor 失败时跨一个 training step 重试；只有 consumer buffer drain 完成后才上抛持久失败；跨 role 继续 cleanup，并保留 residual sweep。PR 增加 DELETE retry、deferred shard cleanup、cancellation、multi-role cleanup 等 regression tests。
- **为什么重要：** 异步 Agentic RL 的数据/trajectory tensor 生命周期不是“异常就退出”这么简单；cleanup 必须跨 worker、跨 role、可重试且不产生 orphan resource。
- **来源：** [AReaL PR #1647](https://github.com/areal-project/AReaL/pull/1647)

### AReaL：Ascend PR gate 调整到 8 NPU runner（Merged）

- **日期：** 2026-08-28
- **状态：** **Merged**

### SGLang：按 warmup 实测重做 CUDA graph pool sizing（Open PR，未合并）

- **日期：** 2026-08-28 至 2026-08-29 持续更新
- **状态：** **Open / 未合并**
- **PR：** `#36911 [Memory] Size the CUDA graph pool from warmup measurements and fix graph-pool borrowing`
- **摘要：** PR 针对 speculative decoding 负载下 graph-pool fragmentation / borrowing 失败：用 eager warmup 实测 reserved footprint 预切连续 pool；从所有 segment 中寻找连续 inactive run；借用 arena 改 best-fit；并撤回 EAGLE verify sampling 的不安全 borrowing。作者报告在 GB300 TP4/EP4 形状下 borrowable free 从 7.35GB → 9.68GB，largest run 从 1.13GB → 2.30GB。
- **为什么重要：** Serving 的瓶颈已深入到 CUDA allocator / graph capture / speculative decoding 的交互层，真正 production inference infra 要理解显存几何和生命周期，而不是只调 batch size。
- **来源：** [SGLang PR #36911](https://github.com/sgl-project/sglang/pull/36911)

## 9. 对职业与技术路线的影响

### 今天最值得深入学习的 3 个技术点

**1. Reward / Evaluator Sandbox。**  
不要只学 GRPO 数学，重点补齐 reward worker 如何隔离执行、schema validation、timeout、resource limit、network deny、artifact audit，以及怎样避免 policy output 直接污染 grader process。verl #7607 是极好的真实案例。  
入口：[verl #7607](https://github.com/verl-project/verl/pull/7607)

**2. Experiment Runtime / Env-as-a-Service 的上层语义。**  
把环境抽象从 `sandbox_id + exec` 提升到 `experiment/session + hidden assets + policy + evaluator + trajectory + artifact + TTL + replay`。Anthropic AAR 和 DeepMind double-blind eval 已经给出了需求来源。  
入口：[Anthropic AAR](https://alignment.anthropic.com/2026/automated-alignment-researchers/) / [DeepMind](https://deepmind.google/blog/piloting-the-worlds-first-double-blind-ai-evaluations/)

**3. 异步 RL / Serving 的资源生命周期。**  
AReaL RTensor cleanup、SGLang graph pool、LMCache DCP/Mamba geometry 都说明：高价值 Infra 能力正在集中到 **state ownership、backpressure、cleanup、memory geometry、topology-aware scheduling**。  
入口：[AReaL #1647](https://github.com/areal-project/AReaL/pull/1647) / [SGLang #36911](https://github.com/sgl-project/sglang/pull/36911) / [LMCache #4809](https://github.com/LMCache/LMCache/pull/4809)

### 可能形成岗位机会的趋势

- **Agent Runtime / Sandbox / Secure Execution**：尤其是能连接 K8s / VM / microVM，并处理 secrets、network policy、workspace、snapshot、audit 的控制面。
- **Agentic RL Infra / Automated Research Platform**：rollout、trajectory、reward/eval、experiment scheduling、异步数据流与算力调度的融合。
- **Inference Systems**：speculative decoding、KV cache、disaggregated serving、memory allocator、multi-backend kernel routing 会继续吃工程人才。

### 哪些更像短期热点

单纯围绕某次 benchmark 榜单做“模型谁强 2%”的追逐价值较低；没有独立 eval、没有真实任务成本、没有 serving 约束的榜单变化，不值得投入太多时间。相反，**模型自己参与训练/系统优化后，如何让它安全、可规模化地操作真实环境**，是更稳定的长期问题。

### 一个可执行的实践建议

这周可以做一个很小但有含金量的 Demo：

```text
Agent / RL Trainer
      ↓
Experiment API
      ↓
Sandbox Runtime
  ├─ workspace
  ├─ network policy
  ├─ reward/evaluator subprocess
  ├─ hidden test assets
  ├─ TTL / cleanup
  └─ trajectory + audit log
```

先只支持 Kubernetes Pod/Kata 一种 runtime，但把 **reward/evaluator 隔离、hidden test mount、trajectory replay、TTL GC** 做完整。这样项目叙事不是“又封装了 K8s”，而是 **Agentic RL / Automated Research 的可信 Environment Control Plane**。
