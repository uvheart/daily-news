## 今日概览

### 【一句话判断】

今天最明显的变化，是 **Agent 正在从“模型 + tool call”变成真正的实时分布式运行时**：Google 的 Gemini 3.8 Live 已经把持续语音/视觉输入、97 种语言切换、异步函数调用、后台工具执行和边对话边推理放到同一条 Live API 路径里，Agent Runtime 要开始认真处理 session、并发、backpressure、tool latency 和可中断任务，而不是只做同步 request/response。

另一条更长期的主线是 **后训练与基础设施正在成为模型差异化本身**：Salesforce Koa 直接用企业场景 synthetic trajectories + SFT + GRPO 做 CRM reasoning；NVIDIA 把基础设施指标从峰值 FLOPS 转向“agentic tokens per megawatt”；PyTorch、verl、SGLang 又继续把 RDMA transport、权重同步、FP8/FP4、KV/推理数据面往框架底层下沉。未来 AI Infra 的核心越来越像“Environment/Runtime + RL Data Plane + Serving Data Plane + Resource Control Plane”的组合。

### 【与用户最相关的 3 个信号】

1. **Environment-as-a-Service 应该继续往“实时 Session Runtime”而不是 VM/Pod 管理系统走。**  
   Gemini 3.8 Live 暴露出来的是一个长生命周期 Session：音频/视觉流持续进入，模型持续生成，工具在后台异步执行，结果随时回灌。对应的 Infra 对象至少要有 `Session / Task / ToolCall / Lease / Cancellation / EventStream / Artifact / Policy`，而不是 `createSandbox()` 后等一个 HTTP response。

2. **Agentic RL 的工程壁垒正在变成“Environment + Verifier + Weight/KV Data Plane”。**  
   Koa 说明企业高质量 RL 数据来自可执行领域流程；HazardAuditor 说明安全 reward 可以来自 sandbox 的真实执行 outcome；verl/PyTorch 又在解决 weight/tensor transport。把这三层连接起来的人，比只会套 GRPO 算法的人更稀缺。

3. **GPU/集群控制面要开始按“任务产出”而不是按“机器占用率”做优化。**  
   NVIDIA 今天强调 agentic tokens/MW，背后其实是同一个趋势：未来 scheduler 需要把 token throughput、tool latency、trajectory success rate、KV 占用、sandbox 启动时间、功率与成本放到同一个 SLO/feedback loop 中。

### 4. Agent / Coding Agent / Computer Use

#### 4.1 Realtime Agent 的新核心：异步工具执行和连续 Session

Gemini 3.8 Live 的关键不只是 voice。它意味着一个 Agent session 内可以同时存在 **streaming multimodal input、model reasoning、speech output、background tool/API calls 和用户新的输入**。对应的 Harness 至少需要：

- session-level event log 与 monotonic sequence；
- tool call 的 async job handle、deadline、cancel/retry；
- tool result 回灌与 stale-result 防护；
- 输出音频与 reasoning/tool completion 的优先级调度；
- 跨 session quota、admission control 和 backpressure。

来源：[Gemini Live API 官方说明](https://blog.google/innovation-and-ai/technology/developers-tools/build-real-time-voice-applications-gemini-audio/)

#### 4.2 Gavel：Skill/Tool Routing 可能从 RAG 变成 Agent 模型内部能力

- **发布日期：** 2026-09-14
- **摘要：** Gavel 通过冻结 LLM hidden state 做 skill routing，只训练轻量映射，并支持 rollout 中途重新选 skill。
- **核心技术点：** hidden-state router、skill bank、Glance + Verdict、mid-trajectory routing、SkillTraj。
- **为什么重要：** 当 Coding Agent 有几十个 MCP server、几百个 skill 时，把所有 schema/description 永久塞进 context 既贵又污染注意力。未来更合理的架构是 **capability registry + router + on-demand mount**。
- **来源：** [arXiv](https://arxiv.org/abs/2609.15982)

#### 4.3 Computer Use 安全评价开始走向“执行环境内测量”

HazardAuditor 不是只从文本判断“这一步危险不危险”，而是在 controlled environment 中真正执行 Agent，再把异构 agent interaction 统一成 canonical event。这一设计比传统 prompt guard 更贴近真实 Computer Use 风险。

来源：[HazardAuditor arXiv](https://arxiv.org/abs/2609.15134)

### 5. Agentic RL / RL Infra

#### 5.1 Koa 是很值得研究的企业 Agentic RL 样本

- **发布日期：** 2026-09-15
- **训练方式：** SFT + GRPO；训练工具包括 NeMo RL、NeMo Gym、NeMo AutoModel。
- **数据形态：** synthetic CRM scenario，包含业务 sequence、action、tool call，而不是只做静态 QA。
- **Runtime/安全：** Salesforce 自持权重，强调训练/推理在自己的 trust boundary 内，并支持更私有化的安全部署场景。
- **判断：** 企业 Agentic RL 很可能不是“拿公开 benchmark 做 GRPO”，而是围绕内部 workflow 建 `Environment + simulator + verifier + trajectory store + policy training`。
- **来源：** [Salesforce Koa 官方公告](https://investor.salesforce.com/news/news-details/2026/Announcing-Koa-Salesforces-First-CRM-Reasoning-Model-Built-on-NVIDIA-Nemotron/default.aspx)

#### 5.2 verl 的 DeepSeek V4 FP8 delta sync：权重分发正在成为 RL step 的一级成本

- **状态：** open PR，2026-09-15 持续更新，未合入。
- **摘要：** PR #7676 面向 Megatron trainer → SGLang rollout server 的 DeepSeek V4 权重同步，尝试保留 checkpoint 原始 `ue8m0` FP8 representation 与 scale，加入 exact-length P2P、24-bit positions、cross-rank amax compaction 与 fail-closed verification。
- **提交者测试：** 在其 40×B300 两步训练配置中，`delta_sharded` steady weight sync 相比 full NCCL 报告约 14.66× speedup；后续 P2P 与 position packing 又进一步降低 payload/wall time。因为仍是 PR 且 workload 单一，应看作工程方向而非通用性能结论。
- **为什么重要：** Fully async / off-policy RL 的收益会被权重更新耗时、version lag 和 rollout abort 直接吃掉。未来 RL Infra 要把 **weight version、delta transport、atomic apply、verification、rollback** 当成一等状态机。
- **来源：** [verl PR #7676](https://github.com/verl-project/verl/pull/7676)

#### 5.3 GuardPO 展示了另一类 RL：用真实执行 outcome 训练安全策略

HazardAuditor 的 GuardPO 把 sandbox 中可确定的 safety outcome 转成 sequence-level advantage，再对 guard model 的 rationale/verdict 区域做规范化优化。对 Agentic RL Infra 来说，这说明 `reward service` 不一定只是数学题 verifier，也可以是 **execution policy / security outcome / side-effect detector**。

来源：[HazardAuditor](https://arxiv.org/abs/2609.15134)

### 6. Agent Sandbox / Runtime / Infra

#### 6.1 Sandbox 的真正价值正在从“隔离”扩展到“可测量、可训练、可审计”

HazardAuditor 很值得从 Infra 角度看：受控环境不仅为了防 Agent 越权，也负责产生可信的执行真值。一个更完整的 Agent Sandbox 平台应该原生记录：

`session_id -> env_image -> policy -> action/event -> resource/network side effect -> artifact -> verifier outcome -> cleanup status`

这些数据既能用于审计，也能变成 SFT/RL/eval 数据。来源：[论文](https://arxiv.org/abs/2609.15134)

#### 6.2 NVIDIA 把 secure sandbox 启动速度也放进 Agent Infra 性能叙事

NVIDIA 在 AI Infra Summit 文章中引用 Perplexity SPACE secure sandbox 在 Vera CPU 上的启动性能案例，说明 Coding Agent 的 infra benchmark 已经不只看 token/s，也开始把 sandbox startup 纳入端到端 Agent 性能。厂商数字不做跨平台结论，但这个评价维度本身值得保留。

来源：[NVIDIA 官方博客](https://blogs.nvidia.com/blog/ai-infra-summit-vera-rubin-dsx-energy-efficiencies-tokens-per-watt-ai-factories/)

#### 6.3 Enterprise Runtime 的边界会越来越接近“私有云/隔离区 + Agent Policy”

Salesforce Koa 强调模型权重和 post-training/inference 留在自身 trust boundary，并给 Missionforce 等场景提供 private cloud / air-gapped / specialized secure deployment。这说明高价值企业 Agent 最终往往需要同时解决 **模型、数据、工具、网络与执行环境** 的隔离，而不只是 API 鉴权。

来源：[Salesforce Koa 官方公告](https://investor.salesforce.com/news/news-details/2026/Announcing-Koa-Salesforces-First-CRM-Reasoning-Model-Built-on-NVIDIA-Nemotron/default.aspx)

### 9. 对用户职业与技术路线的影响

#### 9.1 今天最值得深入学习的 3 个技术点

**第一：Realtime Agent Runtime 的并发语义。**  
不要停留在 WebSocket/SSE。真正值得研究的是一个 Session 同时跑 model stream、audio stream、tool task、sub-agent 和 user interruption 时，怎么做 event ordering、cancellation、deadline、backpressure、idempotency 与 recovery。Gemini Live 今天已经把这个问题推到生产接口层。来源：[Gemini Live 开发者文章](https://blog.google/innovation-and-ai/technology/developers-tools/build-real-time-voice-applications-gemini-audio/)

**第二：Agentic RL 的 Weight / Trajectory / Verifier Data Plane。**  
Koa 说明 trajectory 来自可执行领域 workflow；verl 说明 weight sync 自己就是一个大型分布式系统；HazardAuditor 说明 sandbox outcome 可以直接成为 reward。把三者串起来，就是下一代 Agentic RL Infra 的骨架。来源：[Koa](https://investor.salesforce.com/news/news-details/2026/Announcing-Koa-Salesforces-First-CRM-Reasoning-Model-Built-on-NVIDIA-Nemotron/default.aspx) / [verl PR](https://github.com/verl-project/verl/pull/7676) / [HazardAuditor](https://arxiv.org/abs/2609.15134)

**第三：Resource Control Plane 从 utilization 转向 outcome-aware scheduling。**  
可以开始把 `GPU utilization` 之外的指标真正纳入调度：`successful trajectories/s`、`agentic tokens/s`、`tool wait time`、`sandbox startup P95`、`KV bytes/session`、`W/session`、`cost/success`。NVIDIA 的 tokens/MW 只是一个明显信号。来源：[NVIDIA AI Infra Summit](https://blogs.nvidia.com/blog/ai-infra-summit-vera-rubin-dsx-energy-efficiencies-tokens-per-watt-ai-factories/)

#### 9.2 可能形成岗位机会的趋势

- **Agent Runtime / Environment Platform：** session control plane、sandbox pool、tool execution、policy/audit、artifact/trajectory store。
- **Agentic RL Infra：** rollout scheduler、environment gateway、reward/verifier service、weight synchronization、async/off-policy correctness。
- **Inference / Data Plane：** remote KV、RDMA transport、prefill/decode disaggregation、model-specific serving kernel、heterogeneous GPU/NPU/ROCm 适配。
- **AI Resource Platform：** 将 GPU、功率、network、KV、token/trajectory throughput 纳入统一 scheduler 与 SLO。

#### 9.3 哪些更像短期热点

“再套一层通用 workflow GUI”“只靠 prompt 拼一个 multi-agent team”“没有可执行 Environment/Verifier 的 Agent benchmark 刷榜”，护城河都比较弱。更长期的是 **Runtime、状态、权限、资源、数据闭环和故障恢复**，因为无论上层换哪个模型，这些问题都会留下。

#### 9.4 一个可执行的实践建议

可以把 `Environment-as-a-Service v0.1` 再推进一步，做一个 **Realtime EnvironmentSession Control Plane**，目标不是多支持一种 VM，而是把今天这些趋势串起来：

```text
EnvironmentSession
├── lease / ttl / owner
├── sandbox runtime (Kata / Firecracker / VM)
├── event stream (model / user / tool / env)
├── async ToolTask
│   ├── deadline / cancel / retry
│   └── idempotency_key
├── policy hook
│   ├── before_action
│   └── after_action
├── verifier / reward
├── artifact + trajectory
├── resource accounting
│   ├── gpu_seconds
│   ├── tokens
│   ├── kv_bytes
│   └── sandbox_start_ms
└── cleanup / orphan-reaper
```

然后做一个最小 demo：**Kubernetes 控制面 + 10～20 个 sandbox，Agent 通过异步 tool call 完成一个 5～10 步任务；中途随机 kill worker / tool task，要求 session 可继续、重复 action 不产生副作用，并完整保留 trajectory 与 verifier outcome。** 这比单独再写一个 Agent Framework 更能体现 Agent Infra / 云原生 / RL Infra 的组合能力。
