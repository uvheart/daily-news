## 5. Agentic RL / RL Infra

### TRL：Triton chunked log-prob
- **合入日期：** 2026-09-25
- **摘要：** #7386 用 Triton kernel 替换原 PyTorch chunked log-prob，LM head 按 tile 投影，使用 online logsumexp；backward 重算 tile 并原地写梯度。
- **核心技术点：** 支持 DPO、KTO、GRPO、RLOO、AsyncGRPO 等路径；16k × 4096 测试里 peak memory 约 2.82 GiB，而 full logits 是 45.08 GiB。
- **为什么重要：** Agentic RL 的训练成本越来越取决于 rollout 之外的 policy logprob / entropy 重算效率。
- **来源：** [TRL PR #7386](https://github.com/huggingface/trl/pull/7386)

### TRL：fused LM head 进入 AsyncGRPO
- **合入日期：** 北京时间 2026-09-26
- **摘要：** #7387 将 patch_chunked_lm_head 重构为 opt-in patch_fused_lm_head，直接返回 loss、log_probs、entropy、label_mask、aux_loss，不再要求 materialize 完整 logits。
- **来源：** [TRL PR #7387](https://github.com/huggingface/trl/pull/7387)

### verl：Blackwell MoE 在线权重同步 correctness
- **合入日期：** 2026-09-24
- **摘要：** #7987 修复 vLLM 在 SM100 默认 serving backend 下，expert 权重 kernel layout 与 checkpoint layout 不一致导致在线同步失败的问题。
- **核心技术点：** checkpoint layout 与 serving kernel layout 分离；采用 live storage view 的 in-place staging，避免整层额外峰值内存。
- **来源：** [verl PR #7987](https://github.com/verl-project/verl/pull/7987)

### AReaL：NUMA / NCCL / checkpoint memory lifecycle
- **合入日期：** 2026-09-24
- **摘要：** #1756 通过物理 CUDA UUID 做 NUMA affinity；在 Megatron gradient finalization 前回收 idle device cache，为 NCCL allocation 留空间；checkpoint owner 释放后清理 pinned-host staging buffer。
- **为什么重要：** 多机 RL 稳定性往往不是算法失败，而是 topology、allocator、NCCL 与 async checkpoint 生命周期冲突。
- **来源：** [AReaL PR #1756](https://github.com/areal-project/AReaL/pull/1756)

## 9. 对用户职业与技术路线的影响

### 今天最值得深入学习的 3 个技术点

1. **Session Authority + Lease + Journal/Checkpoint**：不要只把 Agent Session 理解成聊天记录。更值得掌握的是 writer ownership、append-only journal、committed checkpoint、worker recovery 和 session consistency。
2. **Context / KV Data Plane**：重点研究 external KV backend、warm/cold restore、prefix identity、capacity planning、cache hit SLO、跨实例 state placement。SGLang LMCache + KVSET 结合起来看价值很高。
3. **RL Runtime 的 Training-Serving Consistency**：verl #7987、TRL #7386/#7387、AReaL #1756 放在一起看，rollout 平台必须理解 online weight update、kernel layout、logprob hot path、GPU/NUMA topology、NCCL headroom 和 checkpoint 生命周期。

### 可能形成岗位机会的趋势

值得持续押注的是 **Agent Runtime / Agent Infra / Hosted Harness、Stateful AI Serving / Context Infrastructure、RL Runtime / Rollout Platform / Training-Serving Bridge、GPU Runtime / AI Compute Control Plane、Environment-as-a-Service / Sandbox Platform**。这些方向很适合“后端 + 云原生 + K8S + 分布式系统”背景继续向 AI Infra 深挖。

### 哪些更像短期热点

只包一层 MCP/Tool wrapper、只比较模型榜单几个百分点、只做容器/Firecracker/Kata 启动速度对比却没有 session/state/recovery、只做 Agent UI，都可以作为功能，但很难单独形成长期 Infra 壁垒。

### 一个可执行的学习 / 实践建议

做一个 **Stateful Agent Runtime v0.1**：先实现 Session、Journal、Checkpoint、Worker recovery 和 external state/cache adapter，再用故障注入验证会话能否正确恢复，并记录 resume latency、state restore bytes、cache hit rate 与任务成功率。这个 Demo 比单纯“启动一个 Sandbox”更能体现 Agent Runtime / Environment-as-a-Service 的平台能力。

---

## 今日结论

> **Agent 基础设施正在从“资源调度”进入“状态一致性时代”：Session 要 durable，KV 要 externalize，RL 要保证 training-serving consistency，GPU 资源也开始支持 runtime 级细粒度分区。**

今天最值得持续追踪的不是某个新模型，而是 Qwen Code 的 durable session/failover、SGLang 的 external KV cache、Oracle 的 managed memory、TRL/verl/AReaL 的 RL hot path，以及 PyTorch/Megatron 的动态资源与并行运行时。这些变化共同指向一个更清晰的方向：未来高价值的 AI Infra 平台，会同时管理 **Environment + Session + State + Capability + GPU + Recovery**。
